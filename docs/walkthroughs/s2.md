# S2 walkthrough — Interview AI (hands-on checklist)

Slice close ritual (AGENTS rule 5). Walk every feature yourself: perform the
input, check the expected output. Anything that fails → back to a ticket.
Roadmap flips to `shipped` only when this whole list passes.

Setup: `npm run dev:db`, `npm run db:push`, `npm run db:seed`, `npm run dev`
(+ `npm run worker` in a second terminal for queue/cron features). Test
account: `gladostest+clerk_test@example.com`. The interview needs a real
provider key for live LLM calls — either set `PLATFORM_GOOGLE_API_KEY` in
`.env`, or paste a BYO key under Settings → AI keys (BYO runs free, no bar).
Without any key, only the no-LLM steps below pass (that's expected — the
gateway refuses to spend without a route).

## 1 · Setup screen + first session (T02)

1. Open **/interview**.
   - [ ] You see the scope picker (one project / portfolio / application), the
         project list with skills, quick/deep buttons, the startup-persona copy.
   - [ ] With no projects: the empty state tells you to add one first.
2. Pick a project → **Quick — 5 questions**.
   - [ ] You land on the session page with question 1 visible, status
         `active`, "1 of 5 questions".
3. Check energy (admin: /admin, or your profile's energy display).
   - [ ] Balance dropped by exactly 1 bar (welcome bar +1 at signup may have
         offset it — first-ever session on a fresh account nets to zero).
   - [ ] Starting a second interview at balance 0 shows the honest
         out-of-bars error, not a silent zero-floor.

## 2 · The turn loop (T03)

1. Answer question 1 with something vague ("it was easier").
   - [ ] The interviewer PUSHES by naming the vagueness — "easier than
         what?" — and the turn shows a follow-up marker.
   - [ ] After 2 pushes on the same question it moves on regardless.
2. Answer the rest with specifics; let the session run to question 5.
   - [ ] After the last answer the status flips to `completed` and grading
         starts automatically ("Grading your session…").
3. Pause/resume: start another session, answer one question, kill the dev
   server, restart, reopen the session.
   - [ ] Your answer is still there and the session continues.
4. (Optional, fast path) run `npx vitest run tests/interview-turnloop` —
   the abandon-sweep and bank-regen behaviors are covered there even if you
   don't wait 7 days.

## 3 · Report + evidence (T04)

1. After grading completes, reload the session page.
   - [ ] A report section appears: readiness band, five dimensions (x/4),
         per-question 🟢🟡🔴 next to each turn, probed skills with verdicts,
         groundedness findings (each cites a real turn), coaching Say/Avoid.
   - [ ] The evidence basis line says graded on reasoning quality (no
         records yet) and suggests adding decision records.
2. Check /skills (or /events).
   - [ ] `interview_completed` events exist — one per probed skill — with
         verdict-scaled points; levels moved.
3. Click **Delete session** on the session page.
   - [ ] Transcript and report content are stripped, the session shows the
         honest "deleted — levels from this session no longer count" state, and
         the affected skill levels fell (how-levels-work explains it).

## 4 · Decision records + records-mode grading (T05)

1. On /interview, under "Decision records", hand-write one for your project
   (choice / alternatives / why).
2. Run another interview on the same project; after grading:
   - [ ] The report's basis line now says **graded against your decision
         records**.
3. On the graded report, click **Save the choices you defended**.
   - [ ] Draft records appear; confirm one; it shows `confirmed` and joins
         the project's record list on /interview.
4. Edit the project (change its description), then grade a new session.
   - [ ] The basis flips back to reasoning-quality — your records went
         stale (corroboration-only) when the project changed. Honest.

## 5 · Scopes (T06)

1. /interview → scope **Portfolio**, check 2–3 projects, start.
   - [ ] Question 1 asks which project is your deepest work (the
         cross-project opener), then focus rotates.
2. Scope **Application**, pick a saved JD (or resume-only), start.
   - [ ] Questions probe resume claims and skew toward the JD's skills; the
         report shows the **resume claim audit** section for non-green claims.
3. Try checking 4+ projects in portfolio mode.
   - [ ] Rejected with the cap message (3).

## 6 · Eval harness (T07/T08 — admin)

1. `npm run check` — the golden suite (10 fixtures, citation + validation
   asserts) runs as part of the tests. Already green.
2. /admin → **Grader eval — golden set**.
   - [ ] The run button shows the estimated cost before you press it.
   - [ ] After a run: per-fixture bands, auto-anchored unanimous fixtures,
         release-gate verdict. If a fixture splits, it appears under **Pending
         adjudication** — set its band.
   - [ ] Run twice — the second run compares against anchors and flags DRIFT
         if any band moved.
   - [ ] The voice bench memo and the transcript-storage readout render
         below (storage shows KB vs threshold; "Force tier to R2 now" works with
         R2 keys configured).

## 7 · Weekly briefing (T09)

1. Open **/this-week**.
   - [ ] Five blocks render: activity, points/level moves (both
         directions), interview dimension trends, energy state; one CTA; one
         short coach's note that matches the numbers (never invents one).
2. Click **Unsubscribe**.
   - [ ] The page confirms; `runWeeklyBriefing` skips you (covered by tests;
         real email needs `RESEND_API_KEY` + a verified sender in .env —
         without it the send step self-skips, by design).
3. (Cron) the worker schedules briefing_weekly Mondays 09:00 UTC — visible
   in worker logs at startup.

## 8 · MCP surface (T10)

1. Settings → API tokens → create one (copy it — shown once).
2. Add the server to any MCP-capable harness (config snippet in
   `skills/glados-interview/SKILL.md`), point it at
   `http://localhost:3000/api/mcp`.
3. From the harness: list tools (5), then run the protocol:
   `get_spine_snapshot` → `start_interview_session` (returns the SAME bank
   as the web) → converse on your harness → `submit_interview_transcript` →
   poll `get_interview_report`.
   - [ ] Report arrives graded; /events shows the evidence came from the
         platform grader (submitting alone never wrote events).
4. Submit a 4th transcript in one day.
   - [ ] Its report stays **pending** until the next UTC day (cap 3/day).
5. Try `save_decision_record` WITHOUT `userConfirmed: true`.
   - [ ] Rejected: "ask the user first".

## 9 · Voice posture (T11)

- [ ] `getTranscriptionAdapter()` is parked by design — the memo at
      `docs/prior-art/stt-spike-memo.md` explains why (container cost, not
      latency). The demand button on the report page increments
      `voice.demandCount` (admin panel shows it).

## 10 · Readiness card (T04, flag-gated)

1. Enable the flag: admin → feature flags → `interview.shareCard` = on (or
   insert the row), then reload a graded session.
   - [ ] The **Shareable readiness card** link appears; the card page shows
         band + dimensions only — no transcript, no product wordmark.
